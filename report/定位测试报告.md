# 定位测试报告

记录日期：2026 年 10 月 14 日

## 测试目的与输入

用 `src/localization/maps/scans.pcd` 作为全局地图，将 Fast-LIO 实时累积的
`/Laser_map` 作为局部地图，验证 KISS Matcher 粗配准与 VGICP 精配准能否完成
全局重定位。运行环境为 ROS 2 Humble。`/Laser_map` 的点云位于 `odom`，
全局 PCD 按 `map` 坐标系解释；输入使用 reliable QoS。

定位节点的体素分辨率为 `0.1 m`，粗配准最少需要 20 个内点。
可视化节点另用 `0.3 m` 体素，仅降低 RViz 显示负载，不改变定位输入。

| 初始匹配 / 筛选后匹配 | 5,000 / 1,756 |
| 旋转内点 / 平移内点 | 0 / 0 |
| 粗配准结果 | `solution_valid=false`，未达到 20 个内点 |
| VGICP | 未执行，因粗配准被拒绝 |

下一条局部地图消息有 560,685 个点，降采样后为 128,130 个点。
这些记录表明点云已成功接收、解码和降采样；这一次失败发生在粗配准
的一致性验证阶段。日志只覆盖所展示的匹配尝试，不能据此计算整个测试
过程的成功率。没有 VGICP 结果，也不能据此评价精配准的效果。

## 初步分析

局部图降采样后仍有约 12.5 万点，且提取出约 12.4 万个 KISS 特征点。
因此，本次记录不支持“单纯因为点数太少而匹配失败”的判断。尽管筛选后
仍有 1,756 个候选对应，旋转与平移内点均为 0，说明这些对应未形成算法
认可的一致变换。

当前区域是桌子较多、较空旷的平台；此前楼梯区域的离线点云曾匹配成功。
重复桌椅与相似平面可能让特征对应更难区分，而局部图与全局图的实际
重叠范围、两次建图的场景变化或坐标处理也可能影响结果。这些都是待验证
的解释，不能仅凭截图和这一组日志确定根因。

## 后续验证

1. 在 RViz 中确认局部图确实覆盖全局图的一段，并检查全局 PCD 与
   `/Laser_map` 的坐标定义、雷达到 IMU 的外参和点云单位。
2. 在楼梯、拐角或立柱等较有辨识度的位置再采集累积地图，记录每次
   `initial`、`after_pruning`、`rotation_inliers` 和 `translation_inliers`。
3. 若仍为 0 内点，用人工给定的粗略初始位姿叠加两张地图，先判断
   两图是否有足够的真实重叠，再分别排查特征匹配和配准参数。

本报告依据会话中提供的日志及两张截图整理；没有重新运行定位或
对截图中的点云做定量重叠计算。`scans.pcd` 体积较大，地图文件本身未纳入 Git。
